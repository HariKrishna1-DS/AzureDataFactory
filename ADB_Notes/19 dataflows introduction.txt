spark to execute in massive parallel process--->it requires a cluster

1)Source Transformation:---->To read data from azure/non-azure storages
                             reading from azure storages is faster
       supportable storage sources are
           -azure datalake gen2
           -azure sql database
           -azure synapse
           -azure cosmos              
           -non-azure sources with the help of IR(self-hosted)
            (here writing and exporting takes more time)
            so instead write custimized spark code-->configuring/increasing
            parallel process--->it takes less time
 
           as it takes more time
           solution is:
           1.use copy activity from non-azure to azure datalake
           2.apply dataflow transformations

==============================================================================
2)sink transformation: To write data outputs into target storage systems

    supportable storage targets are
           -azure datalake gen2
           -azure sql database
           -azure synapse
           -azure cosmos              
           -non-azure sources with the help of IR(self-hosted)-->slow
            solution:
            1.use copy activity for non-azure to azure datalake
            2.apply dataflow transformations
            3.take the sink as datalake
            4.use copy activity from datalake to non-azure storages
